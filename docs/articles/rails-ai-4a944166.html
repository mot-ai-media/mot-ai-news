Rails作者が宣言「手でコード書かない」AIが開発現場を完全に変える

Rails作者が宣言「手でコード書かない」AIが開発現場を完全に変える

MOT ANALYSIS

TL;DR Rails作者が所属する企業では手でのコード作成をやめ、AIが主流に。開発者の仕事内容が根本的に変わりつつある。

何が起きたか

Ruby on Railsの作者DHHが、自社の37signalsではコード手書きをやめたことを公開。代わりにAIツール（Claude Opus 4.5など）を中心に開発を進める方針に転換しました。この決定は、開発チーム全体で実施されており、AIの判断に基づいて初期設計から実装までの流れを大きく変えています。

なぜ重要か

プログラミングは長年、人間が手で書くスキルが最重要とされてきました。その考え方が大手企業レベルで覆されることは、業界全体の人材育成・職業訓練のあり方に影響します。また、AIが本当に実務的に「デザイナーからコード生成まで」をこなしている実例が示されたことで、AIの現実的な能力が証明されました。

あなたへの影響

プログラミングを学んでいる人や開発職を目指す人にとって、単なるコード手書き技術だけでは不十分になる可能性があります。一方、AIツールを使いこなす能力や、AIが生成したコードの品質管理、アーキテクチャ設計といった「人間にしかできない判断」がより重要になります。一般のビジネスパーソンにとっても、システム開発の外注や内製の判断基準が変わるかもしれません。

MOT読者が知っておくべき理由

AIが「こんなことはさすがにできない」と思われていた領域（ソフトウェア開発）に本格侵攻している具体例を知ることで、自分の職業や事業がどう変わるのか考えるヒントになります。

知らないと生まれる差

開発スキルの定義が急速に変わることで、既存の開発者教育が陳腐化したり、技能習得の時間が無駄になったりする懸念があります。企業側もAIの判断に依存しすぎると、深刻なバグや設計ミスに気づきにくくなるリスクもあります。

これを知ることで得られるチャンス

開発者は退屈なコード作成から解放され、より創造的な設計やユーザー要件の深掘り、複雑な問題解決に注力できるようになります。また、AIツール活用スキルを身につけた開発者の市場価値は高まる可能性があります。

MOTの見解

DHHの主張する「ソフトウェア開発の未来は明るい」は、一見逆説的です。しかし彼の論点は、人間の生産性が100倍1000倍になれば、仕事の量も質も激変するということ。写真術の発明がカメラマンの職業を消滅させず進化させたように、AIも開発職そのものは変わるが消滅はしないという歴史的な視座が背景にあります。

今後の注目ポイント

37signalsが今後どの程度の規模・複雑度のプロジェクトでAI開発を成功させるのか、また他の大企業がこのモデルを追随するのかが重要です。同時に、AIが生成したコードの長期的な保守性や業界の品質基準がどう変わるのかも注視する価値があります。
