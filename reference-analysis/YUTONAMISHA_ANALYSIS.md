# ゆとなみ社 デザイン分析

## 調査方法についての正直な前提

このセッションには実ブラウザ・Chrome DevTools・スクリーンショット取得ツールがない。
`WebFetch`(HTML→テキスト要約)のみで調査した。そのため以下は不可能:

- 実測ピクセル値(余白px、フォントサイズpx)の取得
- 実際のスクロール体験・アニメーションの目視
- レスポンシブブレークポイントでの実際の崩れ方の確認

以下の分析は「DOM構造・見出しテキスト・画像枚数・ナビゲーション項目」という
テキストとして取得できた実データと、そこから逆算できる設計判断に基づく。
実測できない部分は「〜と推測される」と明記する。

## A. DESIGN INTENT

「経営として銭湯を存続させている」という事実そのものを見せることで成立している。
飾った高級感ではなく、**現役で稼働している現場の説得力**。テーマパーク的な
"銭湯文化の演出"ではなく、実際に人が毎日働き、客が入っている場所の記録に近い。

## B. BRAND WORLDVIEW

UIから逆算すると、このブランドが大切にしているのは:
- 個々の銭湯の固有名(サウナの梅湯、容輝湯、源湯…)を消さないこと → 買収して均質化するのではなく、それぞれの個性を残す経営思想がナビゲーション構造にそのまま出ている
- 代表個人の顔と名前を隠さないこと(「代表 湊三次郎」が独立ナビ項目)
- 「銭湯コンサルティング」「採用情報」まで並列に置く → 銭湯を守る運動そのものが商材であることを隠さない

## C. UX PRINCIPLES

推測される訪問者の視線の流れ:
1. トップビジュアル(銭湯の実写)で「これは実在する場所の話だ」と認識する
2. 銭湯紹介グリッド(10軒)で「思ったより手広くやっている」と規模を把握する
3. 個別の銭湯名をクリックし、自分の生活圏に近い銭湯を探す
4. NEWS/採用/コンサルへ流れ、単なる観光ではなく「関わり方がある」ことを知る

「速く情報を探させる」設計ではなく、「銭湯という具体的な場所を通じてブランドの
本気度を確認させる」設計と推測される。

## D. INFORMATION ARCHITECTURE

ナビゲーションの実データ(取得済み):
`ゆとなみ社 / ご紹介 / 代表 湊三次郎 / NEWS / 採用情報 / お問い合わせ / 銭湯紹介 /
(個別銭湯8〜9軒の固有名) / 銭湯のマナーやルール / オンラインショップ / 銭湯コンサルティング`

会社情報と個別施設情報が**同列のナビゲーション階層**に並んでいる。一般的な企業サイト
なら「会社概要」の下に施設一覧が畳まれるところを、施設名を主役級の項目として扱って
いる → 「会社」より「個々の現場」を情報構造上も上位に置いている。

## E. TYPOGRAPHY

CSSの直接取得はできなかった(外部スタイルシート)。ただし見出しテキスト自体
(「銭湯紹介」「オリジナルグッズ」「NEWS」)が短い名詞のみで、説明的なコピーが
見出しに乗っていない。**見出しが機能名を素っ気なく名乗るだけ**で、煽り文句や
比喩的なコピーを避けている。

## F. LAYOUT

銭湯紹介セクションのみ複数列グリッド(10項目)。ヘッダー・トップビジュアル・グッズ・
NEWSは単一の帯として縦に並ぶ(セクション区切りに`<section>`タグではなく画像バナーを
使用)。**グリッドは「実在し数えられるもの」にだけ使われ、それ以外の帯は1本道**。

## G. SPACING

実測不可。ただしセクション数が約7と少なく、1画面に詰め込む情報を絞っていると
推測される。

## H. COLOR

CSS未取得のため直接の値は不明。ただし写真(銭湯の夜景・照明)自体が暖色の情報源に
なっており、UI側で装飾色を足す必要が薄い構成と推測される。

## I. IMAGE / PHOTOGRAPHY

- トップ:実写1枚(`top_main_land.jpg`)
- 銭湯紹介:実在10軒、各1枚(グリッドで実際の外観)
- ロゴ/アイコン画像が複数(円形ロゴなど)

image/textの比率は「1項目=1枚の実写+固有名」で一定。**ストック素材や装飾用の
汎用写真が見当たらない**(取得できた画像ファイル名はすべて自社ロゴか実写と推測される
命名)。

## J. GRAPHIC LANGUAGE

`<section>`タグ不使用、装飾線やアイコンの多用も確認できない。**足し算より引き算**。

## K. MOTION / INTERACTION

実ブラウザで確認できていないため不明。DOM構造からは大掛かりなパララックス等の
仕掛けを示す痕跡は見当たらない。

## L. RESPONSIVE

実機確認不可。ナビゲーションが「Group1/Group2」的な階層構造を持つ点から、
モバイルではドロワー的にグルーピングごと畳む設計を採用している可能性が高いが未検証。

## PHYSICAL DESIGNとして見たときの例え

雑誌でいえば、表紙(トップビジュアル)→目次(銭湯紹介グリッド)→広告ページ(グッズ)→
奥付(NEWS/会社情報)という、**実用書に近い編集構成**。ビジュアルマガジンのような
大胆な余白・見開き構成ではなく、「必要な情報に早く辿り着ける実用の書式」に近い。
